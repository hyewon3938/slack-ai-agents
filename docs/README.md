# 문서 안내

이 폴더의 문서는 두 종류다. 종류에 따라 믿는 범위와 고치는 시점이 달라진다.

## 문서 종류

| 종류 | 내용 | 고치는 시점 |
| --- | --- | --- |
| 현황 문서 | 지금 코드가 어떻게 생겼고 어떻게 동작하는지 적은 문서 | 코드가 바뀔 때 함께 고친다 |
| 기록 문서 | 그때 어떤 판단을 했고 어떤 과정을 거쳤는지 적은 문서 | 쓴 뒤에는 고치지 않는다 |

현재 상태를 확인할 때는 현황 문서와 코드 맵을 근거로 삼는다. 기록 문서에 나오는 파일 이름과 수치는 쓴 날짜의 값이라 지금과 다를 수 있다.

## 폴더

| 경로 | 종류 | 내용 |
| --- | --- | --- |
| `docs/code-map/` | 현황 | 코드에서 자동으로 만든 파일, 라우트, 크론, Slack, DB 목록 |
| `docs/features.md` | 현황 | 기능 목록 |
| `docs/domains/` | 현황 | 도메인별 스키마, API, 로직 |
| `docs/conventions.md` | 현황 | 코드 컨벤션과 보안 체크리스트 |
| `docs/ops/` | 현황 | 백업, 모니터링 같은 운영 절차 |
| `docs/explainers/` | 현황 | 인사이트 기능을 처음 읽는 사람에게 설명하는 글 |
| `docs/adr/` | 기록 | 되돌리기 어려운 설계 결정 |
| `docs/design-notebook/` | 기록 | 큰 기능의 설계 과정 |
| `docs/optimization/` | 기록 | 성능과 비용을 개선한 과정 |
| `docs/history/`, `docs/project-history.md` | 기록 | 프로젝트 연혁 |

## 코드 맵

`docs/code-map/`은 `scripts/code-map/`이 코드를 읽어 만든다. 코드를 바꾼 뒤 아래 명령으로 다시 만들어 같은 커밋에 넣고, 손으로는 고치지 않는다. 읽는 순서와 한계는 [code-map/README.md](code-map/README.md)에 있다.

## 검사 명령

| 명령 | 하는 일 |
| --- | --- |
| `yarn code-map` | 코드 맵을 다시 만든다 |
| `yarn code-map:check` | 코드 맵이 지금 코드와 같은지 확인하고, 다르면 파일 이름을 출력하며 실패한다 |
| `yarn docs:check` | 모든 문서가 한 종류로 등록됐는지, 현황 문서에 적힌 경로가 실제로 있는지 확인한다 |
| `yarn docs:freshness -- --base <ref>` | 현황 문서가 설명하는 코드가 바뀌었는데 문서는 그대로일 때 경고를 낸다 |

앞의 세 검사는 CI에서 실패하면 PR이 막히고, 마지막 검사는 경고만 남긴다.

## 문서 등록

문서의 종류는 [doc-manifest.json](doc-manifest.json)에 적는다. 새 문서를 만들면 `documents`에 항목을 추가하고, 이미 등록된 글롭에 맞는 경로면 추가할 것이 없다.

- `glob`: 문서 경로 또는 글롭
- `kind`: 현황 문서는 `current`, 기록 문서는 `record`
- `sources`: 현황 문서가 설명하는 코드의 글롭 목록. 이 범위의 파일이 바뀌면 `docs:freshness`가 문서를 다시 보라고 알린다

현황 문서에 적었지만 고치기 어려운 옛 경로는 `scripts/docs/known-broken-refs.json`에 올려 두고, 문서를 고치면 목록에서 지운다.
