# 수면 인사이트 강화 — 점수 다각화·입력 정밀화·대시보드 확장

> 마스터 이슈: #588
> 시작: 2026-07-10
> 상태: 진행 중

## 개요

수면 기록(취침/기상/중간기상/낮잠/메모)은 꾸준히 쌓이는데 활용 층이 얇았다. 점수는 취침시각 표준편차 하나(규칙성)뿐이고, 슬랙 자연어 입력은 명시 날짜 소급 기록·낮잠/밤잠 경계에서 오기록이 났고, 분할 수면(한 밤을 여러 구간으로 끊어 기록)은 대시보드 집계에서 유실됐고, 대시보드는 조회 전용이었다.

이 마스터는 기존 기록 항목만으로 수면의 질을 4축+종합으로 점수화하고, 입력 정확도를 프롬프트 규칙으로 끌어올리고, 대시보드에서 직접 기록까지 가능하게 만든다. 파생 점수는 저장하지 않고 원본에서 결정론 계산해 패턴 검증 시스템(signal_defs)에도 같은 방식으로 연결한다.

## 핵심 원칙

> 마스터 전체 phase가 이 위에서 진행. 변경하려면 ADR.

1. **점수는 저장하지 않는다** — 원본(sleep_records/sleep_events)에서 결정론 재계산으로 파생. 웹은 API 응답에서 계산, 통계는 signal_defs SQL로 계산. 일별 파생값 저장 컬럼을 의도적으로 폐기한 기존 아키텍처(마이그 078)를 계승한다.
2. **임의값은 코드에 박지 않는다** — 목표 구간·가중치·경계값 전부 상수 모듈로 외부화하고 ADR에 근거를 남긴다 (#434 헌장 ⑤ 적용).
3. **세그먼트가 1급 개념** — 밤잠 = 같은 date의 night 레코드 집합. 합성 규칙(시작=첫 취침, 종료=마지막 기상, 구간 갭=수면 중 각성)은 웹·봇·통계가 공유하는 단일 의미론이다. 짧은 각성(수 분)은 sleep_events, 긴 각성은 세그먼트 분리 — 두 신호를 합쳐 분절도를 측정한다.
4. **memo 원문은 통계에 노출하지 않는다** — 특이사항은 고정 태그 어휘로 구조화해서만 통계 연계 (v2 헌장 ① 상속). memo 자유텍스트는 사람용으로 병행 유지.
5. **슬랙 입력은 자유 자연어 유지** — fast path 정규식 부분추출 금지 원칙 준수. 정확도는 프롬프트 규칙(명시 날짜 few-shot, 낮잠 판정, 세그먼트 기록)으로 확보한다.

## Phase 1: 점수 체계 + 세그먼트 집계 + 대시보드 개편 (2026-07-10)

- 이슈: #589
- 관련 ADR: ADR-0059
- 관련 계획서: `.claude/plans/589-sleep-score-foundation.md`
- 상태: 설계 완료

### 결정 요약

수면 점수를 4축(시간·규칙성·연속성·타이밍)+종합으로 확장한다. 전부 기존 기록만으로 계산 가능하고, DB 저장 없이 웹 API 응답에서 파생한다. 같은 날 night 레코드 여러 개를 "세그먼트"로 합성하는 집계를 도입해 분할 수면 유실 버그(마지막 레코드가 덮어쓰는 문제)를 고치고, 부산물로 수면 효율(누운 시간 대비 실제 수면)까지 얻는다. 스키마는 sleep_events.user_id(nullable 추가)와 sleep_records.tags만 정비하고, NOT NULL 승격은 봇 프롬프트가 user_id를 쓰기 시작하는 Phase 2로 미룬다.

### 의사결정 분기점

- **점수 축 구성**: 3축(타이밍 제외) / 4축 / 5축(주관 질 포함) 검토 → 4축 채택. 타이밍(취침 절대 시각)과 규칙성(흩어짐)은 측정 대상이 다르다 — 매일 새벽 3시에 자면 규칙성 100점이지만 타이밍 0점. 봇의 자정 취침 잔소리 로직과도 일관. 주관 질은 기록 부담 증가라 보류.
- **점수 저장 vs 파생**: 일별 점수 테이블 저장안 기각. 마이그 078이 일별 스냅샷 컬럼을 "원본 재계산이 진실"이라며 폐기한 전례와 충돌하고, 공식 수정 시 과거 데이터 drift 발생. 파생 계산이면 공식 개선이 소급 적용된다.
- **세그먼트 종료 시각 계산**: wake_time 문자열 재파싱 대신 `취침(래핑) + duration_minutes`로 계산. 20:00 경계 래핑 로직이 wake 시각에 오적용되는 엣지(밤늦은 기상)를 원천 회피.
- **규칙성 확장**: 취침 표준편차 단독 → 취침+기상 각각 점수화 후 평균. 기상만 무너지는 패턴(취침은 일정한데 늦잠)을 잡기 위해.
- **낮잠의 점수 반영**: 미반영 유지. 아침잠은 기존대로 밤잠 시간에 합산, 오후 낮잠은 통계 신호(sleep_nap_count)로만 소비. 낮잠을 점수에 벌점화하면 "기록할수록 점수가 깎이는" 역인센티브가 생긴다.

### 포기한 안 / 미룬 항목

- **주관적 수면질(1\~5) 기록**: 미룸. 트리거 = 4축 운영 후 종합점수와 체감 질의 괴리가 반복 관찰되면 5축으로 확장 검토.
- **중간기상 지속시간 기록**: 기각. 사용자 기록 관행이 이미 커버 — 긴 각성(10분+)은 세그먼트 분리로 기록되고, 짧은 각성의 분 단위는 정보 가치 대비 기록 부담(새벽에 시계 확인)이 크다.
- **일별 종합점수**: 미룸. 규칙성이 기간 속성이라 일별 정의가 애매. Phase 1은 기간(1w/2w/1m) 점수만.
- **차트 라이브러리 도입**: 기각. 기존 손수 SVG 관례 유지 — 종합점수 게이지도 인라인 SVG 신규 제작.
- **sleep_events.user_id NOT NULL 즉시 승격**: 미룸(Phase 2). 봇 프롬프트가 아직 user_id 없이 INSERT하므로 Phase 1에서 승격하면 배포 사이 프로덕션 INSERT 실패. nullable 추가+backfill만 하고 승격은 프롬프트 갱신과 같은 PR로.

### 미해결·가설

- **가중치 기본값(시간 0.35 / 규칙성 0.25 / 연속성 0.20 / 타이밍 0.20)은 추정**: 수면 위생에서 총량이 가장 지배적이라는 일반론 기반. 검증 = 운영 2\~4주 후 종합점수가 체감과 어긋나는 주 발견 시 상수 조정 (파생 계산이라 소급 반영됨).
- **기존 데이터의 세그먼트 표현 불확실**: 프롬프트 개선(Phase 2) 전에 기록된 분할 수면이 DB에 2행으로 들어갔는지, 1행+이벤트로 뭉쳐졌는지 미확인 (프로덕션 조회는 /build 시점에 확인). 과거 구간의 연속성 점수는 보수적으로 해석.
- **태그 어휘 초기 10종이 실사용과 맞는지**: memo 실데이터 대조를 /build에서 수행, 어휘는 CHECK 제약이라 확장은 마이그레이션 1개로 가능 (diary meta tag 전례와 동일 경로).
