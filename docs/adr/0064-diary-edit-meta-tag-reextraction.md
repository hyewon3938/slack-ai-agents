# 0064. 일기 수정 시 메타 태그 재추출

- Status: Accepted
- Date: 2026-10-22
- Related: #639
- Tags: data, insight, measurement

## Context

Slack에서 저장한 일기를 조회 메시지의 수정 버튼으로 고칠 수 있게 되면서, 고치기 전 원문으로 만든 `diary_meta_tags`를 어떻게 처리할지 정해야 했다.

- 메타 태그는 하루 일기 1행에서 LLM이 고정 어휘 26종 가운데 해당하는 것을 뽑은 기록이고, 주간 검증 엔진과 발굴은 이 태그를 신호로 읽는다.
- 일기는 생활 기준 오늘 것만 다음 날 05:30 추출 cron이 처리하고, 지난 날짜 일기는 저장할 때 `backfillDiaryMetaTags`로 바로 추출한다.
- 수정은 내용 변경, 날짜 이동, 삭제를 모두 포함한다. 날짜를 옮기면 원래 날짜와 새 날짜 양쪽의 원문이 바뀐다.
- 지난 날짜의 태그를 바꾸면 이미 계산한 주간 검증 수치가 다음 계산부터 달라진다. 지난 측정값을 바꾸는 판단이라 되돌리기 어렵다.

## Decision

원문이 바뀐 날짜의 `diary_meta_tags`는 `source`와 상관없이 지우고 다시 추출한다.

- 원문이 바뀐 날짜는 내용 수정이면 그 날짜, 날짜 이동이면 원래 날짜와 새 날짜, 삭제면 원래 날짜다. 내용과 날짜가 그대로면 아무것도 지우지 않는다.
- 일기 저장과 태그 삭제는 트랜잭션 하나로 처리한다.
- 태그를 지운 날짜에 일기가 남아 있고 그 날짜가 생활 기준 오늘보다 앞서면 `backfillDiaryMetaTags`로 바로 다시 추출한다. 봇은 추출을 백그라운드로 돌리고 바로 답한다.
- 생활 기준 오늘의 일기는 다음 날 05:30 추출 cron이 처리한다.
- `seed_daily_activations`는 다시 계산하지 않는다. 아침 카드에 넘기는 기록이라 검증 결과에 영향이 없고, 주간 검증 엔진은 매주 원본 테이블에서 다시 계산한다.

```ts
// diary-edit-store.ts, 저장과 같은 트랜잭션 안에서
DELETE FROM diary_meta_tags WHERE user_id = $1 AND date = ANY($2::date[])
```

## Alternatives considered

### A. 태그를 그대로 둔다

- 장점: 지난 측정값이 바뀌지 않는다. 추출 비용이 없다.
- 단점: 고친 내용과 태그가 다른 채로 검증에 들어간다. 날짜를 옮긴 일기는 원래 날짜에 태그가 남는다.
- 기각 이유: 사용자가 고친 내용이 그날의 사실이라, 틀린 일기로 만든 태그를 남겨 두는 쪽이 측정을 더 해친다고 생각했다.

### B. 새로 나온 태그만 더한다

- 장점: 기존 태그를 지우지 않아 지난 수치 변화가 적다.
- 단점: 지운 내용에서 나온 태그가 남는다. 날짜 이동과 삭제를 처리할 수 없다.
- 기각 이유: 수정의 상당 부분이 내용을 빼거나 날짜를 옮기는 일이라 추가만으로는 원문과 맞출 수 없다.

### C. 지우고 다시 추출한다 (선택)

- 장점: 태그가 항상 지금 원문에서 나온다. 일기가 하루 1행이라 그날 태그를 통째로 다시 만드는 비용이 작다.
- 단점: 지난 날짜의 주간 검증 수치가 다음 계산부터 달라질 수 있다. 수동으로 넣은 태그도 함께 지워진다.

## Consequences

### 장점

- 수정, 날짜 이동, 삭제 모두 같은 규칙 하나로 처리한다.
- 주간 검증 엔진은 매주 원본에서 다시 계산하므로 별도 보정 작업이 필요 없다.

### 단점 / 제약

- 지난 날짜 태그가 바뀌면 이전 주에 본 검증 수치와 다음 주 수치가 같은 기간에 대해 다를 수 있다.
- 05:00\~05:30 사이에 어제 일기를 고치면 바로 추출과 05:30 cron이 같은 날짜를 두 번 추출할 수 있다. 태그 저장이 중복 행을 무시해 행이 겹치지는 않지만, 두 결과가 다르면 합친 태그가 남는다. 드문 시간대라 그대로 둔다.
- 바로 추출이 실패하면 그 날짜는 태그 없이 남는다. 실패는 오류 로그로 확인한다.
