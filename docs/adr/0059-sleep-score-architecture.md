# 0059. 수면 점수 4축 체계와 무저장 파생 계산

- Status: Accepted
- Date: 2026-07-10
- Related: #588 (마스터), #589 (Phase 1)
- Tags: data, web, insight

## Context

수면 기록은 취침·기상·중간기상·낮잠·메모까지 수집되지만 점수는 규칙성(밤잠 취침시각 표준편차) 하나뿐이었다. 수면시간·기상 편차·중간기상 빈도가 어떤 지표에도 반영되지 않아 "수면의 질"을 한눈에 파악할 수 없었다.

추가 제약:

- 사용자는 수면 중 긴 각성(대략 10분 이상)을 중간기상 이벤트가 아니라 **수면 기록 분할**(예: 00:30-03:00, 03:45-09:00 두 구간)로 기록한다. 그런데 웹 집계(`buildDailySleeps`)는 같은 날 night 레코드를 하나로 가정하고 마지막 레코드로 덮어써 세그먼트가 유실된다.
- 패턴 검증 시스템(#477)은 일별 파생값 저장을 의도적으로 폐기(마이그 078)하고 원본 재계산을 진실로 삼는다. 새 점수도 이 철학과 충돌하면 안 된다.
- 프로젝트 헌장: LLM 텍스트 해석 의존 최소화(v2 ①), 임의 임계치 박지 않기(#434 ⑤).

## Decision

### 1. 점수 4축 + 종합 (0\~100, 결정론)

| 축 | 정의 | 공식 (기간 단위) |
|---|---|---|
| 시간 | 일일 총 수면시간의 목표 구간 충족 | 일별: 구간 `[420, 540]`분 안이면 100, 벗어난 거리 d분에 대해 `100 − (d/180)×100` clamp → 기간 평균 |
| 규칙성 | 취침·기상 시각의 흩어짐 | `취침점수 = 100 − (취침stddev/120)×100`, 기상 동일 → 두 점수 평균 |
| 연속성 | 밤잠 분절도 | 밤당 분절 수 = 중간기상 이벤트 수 + (세그먼트 수 − 1) → 기간 평균 f에 대해 `100 − (f/3)×100` clamp |
| 타이밍 | 취침 시각의 절대 위치 | 일별: 첫 취침이 목표(자정) 이전이면 100, 지각 L분에 대해 `100 − (L/180)×100` clamp → 기간 평균 |

종합점수 = 가중 평균, 기본 가중치 `시간 0.35 / 규칙성 0.25 / 연속성 0.20 / 타이밍 0.20`. 모든 목표값·경계값·가중치는 상수 모듈(`sleep-score-config`)로 외부화.

### 2. 세그먼트 합성이 밤잠의 단일 의미론

- 밤잠 = 같은 date의 `sleep_type='night'` 레코드 집합. 정렬 키는 20:00 기준 래핑 분(기존 `timeToMinutesFromMidnight` 재사용).
- 시작 = 첫 세그먼트 취침, 종료 = `마지막 세그먼트 취침(래핑) + duration_minutes` (wake 문자열 재파싱 회피), 세그먼트 사이 갭 = 수면 중 각성(WASO).
- 부산물로 수면 효율(총 수면 ÷ 누운 시간)을 파생 — 별도 기록 추가 없이 얻는 지표.

### 3. 점수는 저장하지 않는다

웹은 대시보드 API 응답에서 TS 순수 함수로 계산. 통계 시스템은 `signal_defs`에 SQL 신호(단일 SELECT, `$1=user_id, $2=date`)로 등록(Phase 2). 공식이 바뀌면 과거 기간에도 소급 적용된다.

### 4. 특이사항은 고정 태그 어휘

`sleep_records.tags TEXT[]` + CHECK 제약(초기 10종: 악몽·화장실·뒤척임·카페인·음주·야식·스트레스·소음·통증·온도). memo 자유텍스트는 사람용으로 병행 유지, 통계는 태그만 소비. 어휘 확장은 diary meta tag 전례처럼 마이그레이션으로.

## Alternatives considered

### A. 일별 점수 테이블 저장

- 장점: 조회 빠름, 봇·웹이 같은 값을 읽음
- 단점: 공식 수정 시 과거 데이터 drift, 마이그 078이 폐기한 구조의 부활, 쓰기 경로마다 재계산 트리거 필요
- 기각 이유: 재계산 아키텍처 철학과 정면 충돌

### B. LLM 평가 기반 질 점수

- 장점: 메모 뉘앙스까지 반영 가능
- 단점: 재현 불가, 비용, v2 헌장 ①(텍스트 의존 최소화) 위반
- 기각 이유: 헌장 위반 + 점수는 추적 가능해야 하는 지표

### C. 단일 종합점수만 노출

- 장점: UI 단순
- 단점: 점수가 왜 떨어졌는지 진단 불가 — 행동 개선으로 이어지지 않음
- 기각 이유: 이 기능의 목적 자체가 원인 파악

### D. 4축 + 종합, 무저장 파생 (채택)

- 장점: 기존 기록만으로 계산, 소급 적용, 통계 연계 무마찰, 축별 진단 가능
- 단점: 요청마다 계산 비용(기간 최대 1개월 × 레코드 수십 건 — 무시 가능 수준), 봇·웹이 공식을 공유하려면 모듈 위치 조정 필요(현재는 웹 전용, 봇은 SQL 신호로 별도 계산)

## Consequences

### 장점

- 규칙성 단일 지표 → 4축 진단 + 종합. 분할 수면 유실 버그가 구조적으로 해소.
- 수면 효율·WASO가 추가 기록 부담 없이 파생됨.
- 태그로 "특이사항 → 다음날 영향" 류 가설을 패턴 검증 시스템이 다룰 수 있게 됨.

### 단점 / 제약

- 규칙성이 기간 속성이라 일별 종합점수는 정의하지 않음 (미룬 항목).
- 웹(TS)과 통계(SQL)가 같은 개념을 두 언어로 계산 — 공식 변경 시 두 곳 동기화 필요. 완화: 상수·공식을 ADR과 도메인 문서에 단일 기술.
- 가중치 기본값은 추정 — 운영 후 조정 전제.
