# 0051. 예산 모델 단순화 — 자금 단일화 + 목표기간 기준 묶인 돈 일괄 처리

- Status: Accepted
- Date: 2026-06-16
- Related: #539
- Supersedes: ADR 0015, ADR 0018
- Tags: data, budget

## Context

ADR 0015는 "자산 = 즉시 쓸 수 있는 돈" 직관을 위해 할부 2+회차를 INSERT 즉시 자산에서 차감했고, ADR 0018은 그 정책의 예외(목표기간 초과 할부)를 위해 건별 `distribute_to_runway` 토글을 도입했다. 두 결정이 누적되며 **묶인 돈(할부) 반영 경로가 셋으로 분산**됐다:

1. 등록 시점 자산 즉시 차감 (ADR 0015, `distribute_to_runway=true`)
2. 건별 토글로 목표기간 초과분 차감 제외 (ADR 0018, `distribute_to_runway=false`)
3. allocator 현재월 락 (`installmentSum`, `isNew` 제외)

여기에 `exclude_from_budget=true` 할부는 1·3 어디에도 안 잡히고 결제주기 정산에서만 처리되어, **네 번째 사각지대**가 존재했다.

이 분산 구조는 자산이 사용자 수기 갱신 전제로 동작할 때 깨진다. 사용자가 자산 금액을 직접 입력하면 등록 시점에 반영됐던 미래 회차 차감(경로 1)이 덮어써지고, allocator는 현재월 회차(경로 3)만 락에 반영하므로, **목표기간 창 안의 미래 할부가 자유 예산 계산에서 누락**된다. 결과적으로 자유 예산이 과대 계상된다.

또한 자산이 `balance` / `available_amount` 이중 필드 + 다중 자산 행으로 나뉘어, 매 결제주기 수기 갱신 시 "어떤 값을 넣어야 하는가"가 직관적이지 않았다.

근본 원인은 **"reservation(미래 의무를 자유 예산에서 예약)"과 "depletion(실제 결제 시 자금 차감)"이라는 별개의 두 회계 동작을 한 메커니즘(등록 시점 자산 차감)에 섞은 것**이다.

## Decision

묶인 돈 처리를 **목표 기간(target_date) 창 기준 일괄 reservation**으로 단일화하고, 자산을 단일 "자금" 필드로 통합한다. depletion은 결제주기 종료 정산 1곳으로 일원화한다.

### 1. 자금 단일화

- 비상금(`is_emergency=true`)을 제외한 자산을 단일 "자금" 자산으로 통합
- 자금의 입력 의미 = **"현금 유동자금"** (= 통장 잔액 − 지난 결제 대금). 사용자가 매 결제주기 경계에서 수기 갱신
- `balance`/`available_amount` 이중 표시 제거 — UI는 자금 단일 숫자 + 비상금 별도
- 자금 음수 허용 (한도 당겨쓰는 마이너스 계좌 의미). 기존 cascading fallback 차감 로직 제거 (단일 비상금-제외 자산이므로 불필요)

### 2. 묶인 돈 = 목표기간 창 기준 일괄 reservation

목표 기간 창 = `[현재 결제월, target_date]`.

```
묶인 돈(L) = Σ 창 안 [할부 회차(billing_month 기준) + 고정비(월별) + 예정지출]
자유 예산   = 자금(F) − L,  창 일수로 균등 분배
```

- 할부 회차는 `billing_month`가 창 안이면 전부 묶인 돈. **창 밖(target_date 이후) 회차는 무시** — 목표 기간 이후는 별도 처리 전제
- 건별 구분 없음. 모든 할부를 동일 규칙으로 처리
- 현재 결제월 회차(1회차 포함)는 **현재월 락**에 귀속 → 현재 주기 자유 예산을 깎되 "오늘 예산"엔 안 몰림 (아래 4 참조)

### 3. 건별 토글 제거

- `distribute_to_runway` 토글(ADR 0018) 제거 — 목표기간 창이 곧 차감 범위이므로 건별 의도 표현 불필요
- 할부별 `exclude_from_budget` 토글 제거 — 할부는 항상 묶인 돈. (`exclude_from_budget`은 **일반 지출**의 세금 등 제외 용도로만 존속)
- 목표기간(target_date) 변경 시 자산 보정 로직 제거 — 묶인 돈을 매 조회 시 라이브 계산하므로, 창이 바뀌면 자동 반영. 변경 모달·자산 delta 보정 불필요

### 4. 할부 1회차 = 자유지출 → 묶인 돈

- 기존: 할부 1회차는 현재 주기 `flexibleSpent`(자유지출)로 잡혀 "오늘 예산"을 즉시 깎음
- 변경: 할부 1회차도 묶인 돈(현재월 락). `flexibleSpent`에서 할부 전체 제외
- 효과: 할부 결제는 "오늘 예산"에 안 몰리고 **현재 주기 자유 예산 전체를 균등하게** 깎음. 할부의 본질(분산 결제)과 일치

### 5. depletion 일원화 — 결제주기 종료 정산

- 등록 시점 자산 즉시 차감(ADR 0015 경로 1) **제거**
- 결제주기 종료 정산에서 **그 주기 실제 결제분 전체**(`billing_month=주기`인 모든 `type='expense'`)를 자금에서 차감, 수입은 증액
  - 기존 `flex + excluded` → **전체 결제분**으로 확장 (할부 2+회차가 flex·excluded 어디에도 안 잡히던 누락 해소)
- 사용자는 정산 후 수기로 자금 미세 보정 (자잘한 차이 흡수). 수기 입력은 **전체 덮어쓰기**이므로 자동 차감과 충돌해도 최종값은 사용자 입력이 승

### reservation vs depletion 분리

| 동작 | 시점 | 대상 |
|------|------|------|
| reservation (자유 예산에서 예약) | 매 조회 (라이브 계산) | 목표기간 창 안 미래/현재 의무 |
| depletion (자금에서 실제 차감) | 결제주기 종료 정산 | 그 주기 실제 결제분 |

한 할부 회차의 생애: 결제 전 → 창 안이면 reservation(묶인 돈). 결제(주기 종료) → depletion(자금 차감) + 창 밖으로 이탈해 reservation 해제. 이중 카운트 없음.

## Alternatives considered

### A. (선택) 목표기간 창 기준 일괄 + 자금 단일화

- 장점: 묶인 돈 경로 1개로 수렴. 사용자 입력 모델("현금 유동자금")과 코드가 일치. 수기 갱신이 자동 차감을 덮어써도 깨지지 않음. target_date 변경이 자산 보정 없이 즉시 반영. 대량 코드 삭제(토글 UI·보정 로직·모달)
- 단점: ADR 0015·0018 정면 supersede. 할부 결제가 "오늘 예산"에 안 보임(현재 주기 전체에 분산되는 체감 학습 필요). 목표기간이 곧 차감 범위라 **목표기간 만료 시 예산 계산 깨짐**(별도: 수동 연장 + 경고로 처리)

### B. ADR 0015·0018 유지 + 수기 갱신 시 자동 재차감 보정

- 장점: 기존 결정 보존. 변경 최소
- 단점: 수기 갱신 때마다 "어떤 미래 회차가 이미 빠졌는지" 역산해 재차감해야 함 — 분산 구조의 복잡도가 오히려 증가. 사용자 입력 모델 불일치(여전히 "자산 = 미래 할부 제외값") 유지
- 기각: 증상(수기 갱신이 차감을 덮어씀)을 더 많은 보정 코드로 덮는 방향. 근본 원인(reservation/depletion 혼재) 미해결

### C. 자금 단일화만, 묶인 돈은 현행 분산 유지

- 장점: 자산 입력 UX는 개선
- 단점: 묶인 돈 누락(핵심 버그) 미해결
- 기각: 핵심 문제를 안 건드림

### D. 할부 회차를 결제일 기준 정산만으로 처리 (ADR 0018 Alt B 재고)

- 장점: 자연스러운 회계 모델
- 단점: reservation이 사라져 "미래 할부가 자유 예산에 미리 안 보임" — 목표 기간 동안 쓸 수 있는 돈을 과대 인식
- 기각: 본 결정은 reservation(목표기간 창)과 depletion(정산)을 **둘 다** 두되 분리. D는 reservation을 버리는 안

## Consequences

### 장점

- 묶인 돈 반영 경로 4개(즉시차감·토글·현재월락·정산사각) → **1개(목표기간 창 라이브 계산)**로 수렴
- 사용자 입력 모델 일치: "통장잔액 − 지난 대금 = 자금" 한 줄. 미래 할부 수기 차감 불필요
- 수기 자산 갱신과 시스템 자동 차감이 충돌해도 깨지지 않음(reservation은 자금값과 무관하게 라이브 계산)
- target_date 변경이 자산 보정·모달 없이 즉시 반영
- 코드 대량 삭제: `distribute_to_runway` 토글 UI, 할부 exclude 토글, `analyzeTargetDateChange`/`applyTargetDateChange`/`computeInstallmentToggleAdjustment`/`computeExcludeToggleAdjustment`, 등록 시점 자산 차감 분기

### 단점 / 제약

- **목표 기간 만료 시 예산 계산 정지** — `monthCount<=0`이면 빈 결과. 수동 연장 + 임박 경고로 대응(이번 범위)
- 목표 기간이 짧아질수록 같은 자금을 적은 일수로 나눠 일 예산이 상승(구조적). 사용자가 목표 기간을 의식적으로 관리해야 함
- 할부 결제가 "오늘 예산"에 즉시 안 보임 — 현재 주기 전체에 분산. 체감 학습 필요
- `distribute_to_runway` 컬럼은 드롭하지 않고 보존(히스토리·롤백 여지), 단 예산 계산에서 미사용 → 데드 컬럼화
- ADR 0008·0009(일 예산 이중화·일별 로그 기준)는 **유지** — 입력만 바뀌고 `todayBudget`/`todayRecommended` 산식은 불변

### 후속 작업

- [ ] 자산 통합 마이그레이션 (비상금 제외 자산 → 단일 자금, 기존 0 자산 정리)
- [ ] 목표 기간 만료 임박 경고 UI
- [ ] `readFlexibleSpent`에서 할부 전체 제외 검증 (1회차 이중 카운트 제거 확인)
- [ ] 정산 차감 = 전체 결제분 변경 후 자금 추이 검증 (할부 2+회차 누락 해소 확인)
