# 0008. 일 예산 산정 모델 이중화 — 기준 일 예산 + 오늘 예산

- Status: Accepted
- Date: 2026-05-06
- Related: #376
- Tags: data, budget, ux

## Context

자유 지출이 월 자유 예산을 초과한 상태에서 새 수입(이번달 분배 옵션)이 들어오면, 단일 일 예산 모델이 사용자 멘탈 모델과 어긋나는 동작을 보였다.

기존 산식:

```
todayBudget = round(monthBudget / cycleTotalDays)  // 또는 잔여/남은일자 기반 단순 갱신
todayRemaining = todayBudget − todayFlexSpent
```

문제 시나리오:

- 잔여 마이너스 상태에서 수입이 들어와도 잔여가 양수로 회복되기 전엔 효과가 안 보이거나 (가산형), 반대로 기준선이 들썩여 일관된 관리 행동선이 사라지거나 (잔여/남은일자형) 둘 중 하나의 부작용이 발생.
- 잔여 음수 상태에서 잔여/남은일자 산식은 음수 → 0으로 클램프되어 "오늘은 얼마나 써도 되는가"의 기준이 사라짐.
- 결국 사용자는 초과분이 청산되는 흐름을 시각적으로 인지하지 못한 채 "수입이 들어오니 일 예산이 그냥 올랐다"는 인상을 받는다.

자유지출 정의는 ADR 0007에서 통일되었으나, 일 예산 산정은 정의 통일과 별개로 모델 자체의 이중화가 필요했다.

## Decision

일 예산을 두 값으로 분리한다.

```
기준 일 예산 (todayBudget)
  = round((monthBudget − currentMonthIncome) / cycleTotalDays)
  // base = 수입 미반영, 사이클 시작 시 약속, 사이클 동안 사실상 불변

오늘 예산 (todayRecommended)
  = max(0, round((monthBudgetRemaining + todayFlexSpent) / daysFromToday))
  // = max(0, 오늘 시작 시점 잔여 / 오늘 포함 남은 일자)

오늘 남음 (todayRemaining)
  = todayRecommended − todayFlexSpent
  // 음수 가능, UI에서 초과 표시
```

- **기준 일 예산**: 사용자 약속의 시각적 기준점. 사이클 동안 흔들리지 않는 행동 anchor.
- **오늘 예산**: 매일 갱신되는 동적 권장값. 마이너스 상태에선 0으로 클램프되어 회복 모드 진입 신호. 잉여 발생 시 자연스럽게 인상.
- **monthBudget**: month-allocator 결과의 `currentMonth.free`(이미 `currentMonthOnlyIncome`이 포함된 값). base는 day-allocator 안에서 `monthBudget − currentMonthIncome`로 산출하여 수입 영향을 분리한다.
- **수입 처리**: "이번 달 분배" 옵션의 수입(`distribute_to_budget=false`)만 day-allocator에서 잔여 보강용으로 사용. "전체 분배"는 자산 잔액 변동을 통해 monthly free에 이미 반영되어 있다고 가정한다.

UI는 오늘 예산을 메인으로 노출하고 기준 일 예산을 회색 보조 텍스트로 병기한다. 마이너스 상태(`todayRecommended === 0` && `monthRemaining < 0`)에선 별도 "회복 모드" 안내 메시지를 띄워 기준선을 잃지 않게 한다.

`saveDailyBudgetLog`는 budget 컬럼에 `todayRecommended`를 저장한다 (스키마 변경 없음, 의미만 정렬). 과거 로그는 옛 정의로 저장되어 있다.

## Alternatives considered

### A. 단일 일 예산 + UI 가이드 메시지

기존 모델 유지하되 회복/잉여 상태일 때 UI에서 부가 안내만 강화.

- 장점: 코드 변경 최소.
- 단점: 사용자가 수동으로 "지금은 회복 모드구나" 인식해야 함. 산식 자체가 어긋난 상태는 그대로.
- 기각 이유: 산식이 멘탈 모델과 어긋나는 근본 문제를 해소하지 못함.

### B. 단일 일 예산 + 잔여/남은일자 기반 매일 갱신

매일 잔여를 남은 일자로 나눠 갱신하는 단일 동적 값.

- 장점: 산식 단순. 수입·지출에 즉각 반응.
- 단점: 마이너스 상태에서 0으로 떨어지면 그날의 관리 기준이 사라짐. 잉여 시점에 갑자기 인상되어 사용자 혼란.
- 기각 이유: "오늘 얼마까지 쓰는 게 정상인가"의 기준이 휘발됨.

### C. 일 예산 이중화 — 기준 + 오늘 (선택, Decision 섹션에 상세)

기준선은 사이클 락, 오늘 권장값은 동적.

- 장점: 멘탈 모델 일치. 회복 모드에서도 기준선 유지. 잉여 시 자연 인상.
- 단점: UI 복잡도 약간 상승. 1차 구현은 사이클 시작 시점 100% 고정 미보장 (자산 변동 시 base가 약간 흔들림).

### D. 사이클 시작 시점 base 스냅샷 저장

사이클 첫날에 base 값을 DB에 박아두고 사이클 동안 절대 흔들리지 않게 한다.

- 장점: 100% 사이클 락. 자산 변동에도 base 불변.
- 단점: DB 스키마 추가 (snapshot 테이블 또는 컬럼). 사이클 시작 트리거 로직 필요. 1차 구현 범위 초과.
- 기각 이유: 이번 변경의 핵심은 모델 이중화. 스냅샷은 후속 작업으로 분리.

## Consequences

### 장점

- 사용자 멘탈 모델과 일치. 수입 입력 시 "초과 청산 → 회복" 흐름이 자연스럽게 보인다.
- 마이너스 상태에서도 기준선이 유지되어 회복 행동선이 명확.
- 잉여 발생 시 오늘 예산이 자연스럽게 인상되어 사용자가 인지 가능.
- day-allocator 산식이 순수 함수로 유지되어 단위 테스트 작성 용이.

### 단점 / 제약

- UI 복잡도가 약간 상승 (메인 + 보조 두 값 표시).
- 1차 구현은 사이클 시작 시점 100% 고정 미보장. 사이클 도중 자산 잔액이 변동하면 monthly allocator 재계산을 통해 base도 약간 변동할 수 있음.
- `daily_budget_logs.budget` 컬럼의 의미가 과거(`todayBudget`)와 신규(`todayRecommended`)에서 달라진다. 과거 데이터 백필은 하지 않으며 신규부터 새 정의 적용.

### 후속 작업

- [ ] 사이클 시작 시점 base 스냅샷 저장 — 별도 이슈. 자산 변동에도 base 100% 고정 보장.
- [ ] 회복 모드 기간이 N일 이상 지속될 때 추가 가이드 메시지 (예: 고정비 점검 권유).
