# 0050. 검증가능성 사다리 + 예측 장부 — 상위 주기 해석의 인식 지위

- Status: Accepted
- Date: 2026-06-13
- Related: #523 (마스터), #529 (Phase 2), #408 (월/세/대운 5-B)
- Tags: insight, statistics, saju, architecture

## Context

일운(일 단위) 검증 엔진은 off-day 2×2 + e-value + 가족 BH-FDR로 "이 사주 feature가 발현한 날 행동 신호가 달라지는가"를 **실증**한다(ADR-0033\~0042). Phase 1(ADR-0049)이 그 링크 증거를 사주 축으로 모은 개인화 프로필(saju_response_profile)을 만들었다. 이제 이 프로필을 월운·세운·대운 해석으로 확장하려는데, **상위 단위는 일운과 같은 방식으로 검증할 수 없다**:

- **표본 구조의 벽**: 세운은 baseline이 28년 × 1인 = 평생 n=1\~2. 월운은 같은 절기월이 1년에 한 번뿐이라 수년이 지나도 n이 한 자릿수. 대운은 10년 단위라 평생 6\~8개. off-day 2×2도, e-value 누적도, 어떤 빈도주의 검정도 검정력을 못 만든다.
- **그런데 출력은 계속 나가야 한다**: 사용자는 검증 주기와 무관하게 해석·경향 리포트를 받는다(출력 연속성 원칙, [[0048]] 후속 D8). 검증이 길어진다고 카드를 끊으면 안 된다.
- **가장 큰 인식론적 리스크**: 이 프로젝트의 본질은 n=1 자기 실험이고 논리는 "믿든 안 믿든 데이터로 검증한다"이다. 따라서 최대 위험은 **"검증할 수 없는 것을 검증된 것처럼 말하는 것"**이다. 표본이 없는 층에서 통계 주장을 흉내 내는 순간 프로젝트의 신뢰 근거가 무너진다.

즉 "검증 불가"를 숨기지 않으면서도 출력은 끊기지 않게 하는 **인식 지위의 아키텍처**가 필요했다.

## Decision

### 1. 검증가능성 사다리 (이 확장의 헌법)

단위가 커질수록 표본이 기하급수로 줄어 통계 확정 가능성이 떨어진다. 각 층의 **지위를 명시적으로 다르게** 두고, 모든 출력은 자기 층의 지위를 라벨로 동반한다.

| 층 | 단위 | 지위 | 메커니즘 |
|---|---|---|---|
| 일운 | 일 | **실증** | off-day 2×2 + e-value + 가족 BH (Phase 0 교정 후) |
| 월운 | 절기월 | **축적-실증** | 예측 장부(생성→채점) + 누적 기술통계. 월 단위 e-게이트 금지(월 n이 수년간 한 자릿수) |
| 세운 | 입춘년 | **장부 한정 약실증** | 입춘 예측 → 다음 입춘 채점. 수명 내 n=1\~2 — 통계 확정 영구 불가. 1차 가치는 확증편향 차단 규율 |
| 대운 | 10년 | **비실증 추론 레이어** | 검증 불가 명시. 가중치 매트릭스 + 교과서 일반론의 라벨 분리 서사만 |

### 2. 전이 가설을 미검증 가정으로 라벨

상위 단위 해석은 "일 단위에서 측정된 십성·오행 반응이 더 큰 주기에도 같은 방향의 배경 기류로 보존된다"는 **전이 가설**에 의존한다. 이건 검증된 사실이 아니라 **미검증 가정**이다. 명리 내부에서도 운-원국 상호작용으로 방향이 뒤집힐 수 있다는 반론이 있다. 그래서:

- 모든 상위 단위 출력에 전이 가설 hedge를 라벨로 동반한다(통계 주장 금지).
- 예측 장부(아래)가 천천히 채점하는 대상이 바로 이 가설이다.
- 해석 레이어(`composeNarrative`)는 측정 셀과 교과서 셀을 **분리 발화**한다 — "측정상 …"(실제 데이터)와 "교과서적으론 …인데 네 데이터엔 아직 안 잡혀"(미검증)를 절대 섞지 않는다([[0038]] 계승).

### 3. 예측 장부 원칙 (Phase 3 — 스키마 설계 일괄 기록, 코드는 후속)

세운·대운을 직접 통계검증할 수는 없어도, **사전등록된 예측을 사후 채점**하는 장부는 확증편향을 차단하는 규율로서 가치가 있다(Brier 같은 확률점수는 표본이 없어 금지 — 방향 적중과 실측 delta만 기록).

Phase 3에서 추가할 `period_forecasts` 스키마 설계:

```sql
-- 091 (Phase 3): 예측 장부 — 절기월/입춘년 사전등록 → 다음 주기에 채점
CREATE TABLE period_forecasts (
  id            SERIAL PRIMARY KEY,
  user_id       INTEGER NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  period_type   TEXT NOT NULL CHECK (period_type IN ('wolun','seun')), -- 대운은 채점 주기가 수명초과 → 비편입
  period_start  DATE NOT NULL,
  period_end    DATE NOT NULL,            -- 채점 시점
  forecasts     JSONB NOT NULL,           -- top-3 도메인 방향 예측 + no-call(예측 안 함) 명시
  baseline      JSONB NOT NULL,           -- 생성 시점 동결된 비교 기준(사후 변경 차단)
  scored_at     TIMESTAMPTZ,              -- 채점 완료 시점(NULL=미채점)
  outcome       JSONB,                    -- 방향 적중 여부 + 실측 delta (Brier·확률점수 금지)
  created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (user_id, period_type, period_start)
);
```

규율: ① top-3만 예측하고 나머지는 **no-call**(예측 안 함을 명시) — 모든 걸 예측한 척 금지. ② baseline은 생성 시점에 동결(사후 조정 차단). ③ 채점은 방향 적중 + 실측 delta만(확률점수 금지). ④ 과거 대운 retro-fitting 금지(확증편향 기계).

### 4. Phase 2 구현 범위 (이 PR)

검증가능성 사다리·전이 가설 라벨·해석 레이어를 구현한다. 예측 장부는 **스키마 설계만 본 ADR에 기록**하고 코드(`period_forecasts`)는 Phase 3 별도 PR. Phase 2 산출:

- 절기 테이블 2029\~2033 연장(만세력 시한폭탄 해소 — 미연장 시 해당 연도부터 월주/년주 전체 throw). KST 환산 후 날짜 추출(Wikipedia UTC 표 교차검증 + 2028행 일치 확인).
- `period_interpretations`(마이그 089): 해석 동결 저장. `periodFortune` 데일리 슬롯(마이그 090, 08:20).
- 해석 엔진(`derivePeriodContext`→`buildInterpretationPayload`→`composeNarrative`→`renderInterpretationBlocks`).
- fast path 정확일치 `^월운$`/`^세운$`/`^대운$` → 저장 해석 LLM 없이 렌더. 접미·접두형은 기존 fortune_analyses(교과서 레이어)로 하위 호환.

## Alternatives considered

### A. 모든 층을 같은 검증 게이트로 (월/세 e-value)

- 장점: 일관된 메커니즘.
- 단점: 월 n이 수년간 한 자릿수, 세 n=1\~2 → 검정력 0. e-value가 의미 있는 수치를 못 만들고, 그걸 출력하면 "검증된 척"이 된다.
- 기각: 표본 구조상 불가능. 사다리의 존재 이유 자체.

### B. 상위 단위는 출력하지 않음 (검증 안 되니 침묵)

- 장점: "검증된 것만 말한다" 원칙에 안전.
- 단점: 출력 연속성 위반. 사용자는 해석을 계속 원하고, 1년차엔 일운 verified도 공백일 수 있어 카드가 통째로 끊긴다.
- 기각: D8(출력 연속성)과 정면 충돌. 침묵 대신 **지위를 라벨로 동반**하는 쪽 선택.

### C. 과거 대운/세운에 retro-fit해서 "검증" 주장

- 장점: 그럴듯한 적중률 숫자가 나옴.
- 단점: 사후에 데이터에 맞춘 확증편향 기계. 예측이 아니라 후견지명.
- 기각: 영구 기각(마스터 §7). 예측 장부는 **사전등록**만 채점.

### D. 채택안 — 검증가능성 사다리 + 사전등록 장부 (Decision 상세)

- 장점: 검증 불가를 숨기지 않으면서 출력 연속성 유지. 각 층이 정직한 지위를 가짐.
- 단점: "탐색적/미검증" 라벨이 자주 붙어 사용자가 확신을 덜 느낄 수 있음 — 그러나 그게 정직한 상태.

## Consequences

### 장점

- **인식 지위가 아키텍처에 박힘**: 어떤 층의 출력이든 자기 지위 라벨을 강제로 동반 → "검증된 척" 구조적 차단.
- 출력 연속성 보장: measured=0이어도 교과서+누적 기술통계+emerging으로 카드가 끊기지 않음(렌더의 일급 경로).
- 향후 모든 상위 단위 작업의 헌법: 후속 마스터(#408 월/세/대운 매칭 등)가 이 사다리 위에서 진행.

### 단점 / 제약

- 1년차엔 verified 공백 가능(전부 emerging "탐색적" 라벨) — 정직한 상태이나 사용자 체감 신뢰는 낮을 수 있음.
- 예측 장부 첫 유의 표본은 \~1년 후(절기월 1순환).
- **절기 테이블은 2033까지만 수록** — 2034-01부터 다시 시한폭탄(월주/년주 throw). 테이블 구동 방식의 본질상 폭탄은 사라지지 않고 만료 연도가 이동. 갱신 절차: 권위 출처(KASI/uncle.tools)에서 다음 5개년 절기 시각을 받아 KST 환산 → JEOLGI_TABLE append + 경계 테스트. 장기적으로 천문 계산식 전환은 별도 트랙.
