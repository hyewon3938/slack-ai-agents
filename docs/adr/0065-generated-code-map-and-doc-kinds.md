# 0065. 자동 생성 코드 맵과 문서 종류 등록

- Status: Accepted
- Date: 2026-11-24
- Related: #642, PR #653
- Tags: process, docs, tooling

## Context

봇과 웹을 합쳐 소스 파일이 380개를 넘으면서, 기능을 고치거나 정리할 때마다 어느 파일에 무엇이 있는지 다시 찾아야 했다. 손으로 쓴 문서로 이 탐색을 줄이려 했지만 두 가지 문제가 반복됐다.

- 파일을 나누거나 옮기면 문서에 적힌 경로가 그대로 남았고, 문서를 믿고 연 경로가 없는 일이 생겼다.
- ADR과 설계 노트는 쓴 날짜의 내용을 남기는 문서인데, 현재 상태를 설명하는 문서와 같은 폴더에 섞여 있어서 예전 구조를 현재 구조로 읽는 일이 있었다.

문서를 사람이 맞춰 가는 방식은 코드가 바뀌는 속도를 따라가지 못해서, 코드에서 바로 뽑을 수 있는 사실과 사람이 써야 하는 설명을 나눠 관리할 방법을 정해야 했다.

## Decision

코드에서 뽑을 수 있는 사실은 스크립트로 만들고, 사람이 쓰는 문서는 종류를 등록해 종류에 맞는 검사를 건다.

- `yarn code-map`이 TypeScript AST와 마이그레이션 SQL을 읽어 `docs/code-map/` 아래에 파일 목록, 웹 API 라우트, 크론, Slack 리스너, DB 테이블 맵을 만든다. 맵은 커밋하고, CI의 `yarn code-map:check`가 커밋된 맵과 지금 코드가 같은지 확인한다.
- `docs/doc-manifest.json`에 문서마다 종류를 적는다. 현황 문서는 `current`, 기록 문서는 `record`이고, 현황 문서에는 설명하는 코드 범위를 `sources`로 적는다.
- `yarn docs:check`는 등록되지 않은 문서, 현황 문서에 적힌 경로 중 실제로 없는 경로, 맞는 파일이 없는 `sources` 패턴이 있으면 실패한다. 기록 문서의 경로는 검사하지 않는다.
- `yarn docs:freshness`는 현황 문서의 `sources` 범위가 바뀌었는데 문서는 그대로인 PR에 경고를 남긴다. 문서를 고칠 필요가 없는 변경도 많아서 실패로 처리하지 않는다.
- 현재 상태는 코드 맵과 현황 문서를 근거로 판단하고, 기록 문서는 판단 경위를 볼 때만 쓴다는 규칙을 `CLAUDE.md`에 둔다.

확실하게 뽑지 못하는 값은 맵에 싣지 않고 `docs/code-map/README.md`의 한계 절에 적는다. 크론 발송 시각은 DB 설정값이 원본이라 맵에서 뺐다.

## Alternatives considered

### A. 손으로 쓰는 구조 문서 유지

- 장점: 도구가 필요 없고 설명을 자유롭게 쓸 수 있다.
- 단점: 파일을 옮길 때마다 문서를 따로 고쳐야 하고, 빠뜨려도 알려 주는 장치가 없다.
- 기각 이유: 경로가 낡는 문제가 이 방식에서 반복됐다.

### B. 맵을 커밋하지 않고 필요할 때 생성

- 장점: 생성 파일이 diff에 나오지 않는다.
- 단점: 읽기 전에 매번 생성 명령을 돌려야 하고, GitHub에서 바로 볼 수 없다.
- 기각 이유: 맵은 코드를 열기 전에 먼저 읽는 자료라서 저장소에 항상 있어야 한다.

### C. 기록 문서까지 경로 검사

- 장점: 저장소의 모든 문서에서 없는 경로가 사라진다.
- 단점: ADR과 설계 노트는 쓴 뒤 고치지 않는 문서라서, 파일을 옮길 때마다 과거 기록을 고쳐야 한다.
- 기각 이유: 기록 문서의 경로는 쓴 날짜의 사실이라 그대로 두는 편이 맞다.

### D. 커밋하는 생성 맵과 문서 종류 등록 (선택한 안)

- 장점: 코드와 맵이 달라지면 CI가 막고, 현황 문서의 낡은 경로도 같은 PR에서 드러난다.
- 단점: 코드를 바꾸는 PR마다 맵 재생성이 따라붙고, 생성 파일 diff가 PR에 섞인다.

## Consequences

### 장점

- 파일 위치, 라우트, 슬롯, 리스너, 테이블을 찾을 때 맵 한 곳에서 출발할 수 있다.
- 파일 이동과 분할이 문서에 반영되지 않으면 CI에서 바로 실패한다.
- 문서를 읽을 때 현재 상태의 근거로 쓸 수 있는 문서인지 종류로 구분된다.

### 단점 / 제약

- `src/`나 `web/src/`를 바꾸는 PR은 `yarn code-map`을 다시 돌려 맵을 함께 커밋해야 한다.
- 파일 역할 칸은 파일 머리 주석에서 가져오므로, 주석이 없거나 낡은 파일은 역할이 비거나 틀릴 수 있다.
- 추출 규칙은 지금 코드의 작성 관례에 맞춰져 있어서, 슬롯 표나 리스너 등록 방식이 바뀌면 스크립트도 고쳐야 한다. 맵의 수치가 0으로 떨어지는 항목이 생기면 추출 규칙부터 확인한다.
