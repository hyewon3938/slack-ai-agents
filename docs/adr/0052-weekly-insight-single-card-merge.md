# 0052. 주간 인사이트 단일 카드 통합 — routine 단독 발송 + 봇 검증 카드 은퇴 + posterior 노출 제거

- Status: Accepted
- Date: 2026-06-16
- Related: #542
- Tags: process, data, ux

## Context

매주 월요일 #insight에 두 개의 주간 카드가 따로 발송된다:

- **패턴 검증 리포트** — 봇(`weekly-verification.ts` → `buildVerificationBlocks`), 06:00, 결정론 코드. `pattern_links`를 직접 재계산해 통계가 100% 정확하지만 글이 기계적.
- **주간 사주 리뷰** — Claude 앱 routine(`weekly-saju-review-v2`), 08:04, LLM이 `saju_influence_summary` view를 읽어 회고를 자연어로 작성.

둘 다 verified/emerging/e-value/교란을 노출해 **사용자 입장에서 비슷한 카드가 두 번 온다**. 특히 사주 리뷰의 "학습 ▸ 검증됨/검증 중" 섹션은 패턴 검증 카드와 거의 중복이다.

제약·원칙:

- **출력 연속성 원칙** (2026-06-13): 검증이 빈약해도 사용자는 경향 리포트를 계속 받아야 한다(침묵 금지). → 봇 카드를 그냥 끄면 routine이 실패한 주에 검증 현황이 아무에게도 안 가는 침묵 위험.
- **v2 헌장②** (결정론 SQL ↔ LLM 자율 역할 분리): 통계 사실은 결정론이 1차. LLM이 통계 숫자를 옮기면 할루시네이션 위험.
- **카드에 표시되던 `확신 N%`(posteriorP)** 는 사실 Beta-Binomial 사후평균 = **발현일 적중률**인데 "확신"이라는 라벨이 "패턴 확신도"로 오독된다. 게다가 표본(`hit/nActive`)과 거의 같은 정보(중복)다.

## Decision

사용자-facing 카드를 **routine 단독 발송으로 통합**한다. 검증 엔진(봇)과 회고 생성(routine)이라는 *만드는 주체는 합치지 않고*, 사용자가 받는 카드만 한 장으로 모은다.

1. **통합 카드** = 회고(prose) → 이번 주 라이프 메트릭 한 줄 → 패턴 학습(검증중/검증됨/기각 카운트 + 검증중·검증됨 항목, 효과크기 내림차순). routine이 발송.
2. **봇 패턴 검증 카드 발송 은퇴** — `buildVerificationBlocks` 발송 경로 제거. 검증 엔진(재계산·status 전이·교란 조정·`link_weekly_stats` write·발굴)은 그대로 유지.
3. **출력 연속성 보장** — 봇이 월요일 늦은 시각(예: 10:00) 슬롯에서 `saju_weekly_reviews`에 이번 주 발송 기록이 있는지 확인 → 없으면(routine 미발송) "주간 리뷰가 아직 안 왔어, 수동 실행해줘" **알림만** #insight에 발송. 사용자가 routine을 수동 실행하면 평소와 동일한 통합 카드가 온다.
4. **idempotency를 발송 성공 기준으로 보강** — 현재 routine은 *발송 전*에 `saju_weekly_reviews` row를 INSERT해서, 발송 단계에서만 실패하면 수동 재실행이 "이미 발송됨"으로 막힌다. 발송 성공 후 기록(또는 `posted_at` 완료 마킹)으로 바꿔, 미발송 주는 항상 재실행 가능하게 한다.
5. **posterior(`확신 N%`) 노출 제거** — 패턴 강도는 효과크기(`평소보다 N배`), 적중 빈도는 표본(`hit/nActive`), 신뢰 단계는 tier(검증중/검증됨)가 전달한다. posterior는 이 셋과 중복이고 라벨이 오독되므로 카드에서 뺀다. 시드 영향력 top 섹션(posterior를 "본인 패턴 가능성"으로 안내하던 곳)은 통합 카드에 포함하지 않는다.
6. **시드/신호 라벨 단축** — 코드(`insight-labels.ts`)와 routine 표기 규칙 양쪽을 같은 규칙으로 단축(일간 강도→`신약/신강한 날`, 천간·지지 접두 제거, 오행 강도 유지, 신호 `평소보다` 제거). 봇 카드(발굴 후보 등)에도 일괄 적용해 전체 일관.

통계를 routine(LLM)이 옮기는 정확성 리스크는 "**DB에서 쿼리한 값을 그대로 박고 routine이 계산하지 않는다**"를 SKILL 프롬프트에 명시해 가드한다(기존 사주 리뷰도 이미 view 값을 그대로 표시 중 — 신규 위반 아님).

## Alternatives considered

### A. 봇이 통합 카드를 전부 생성 (회고까지 봇이 Claude API 호출)

- 장점: 단일 발송 주체, 타이밍 단순, 통계 정확성 100%
- 단점: 봇에 LLM 프롬프트·사주 해석 로직을 새로 이식해야 하고, 결정론 엔진과 LLM 서사가 한 코드에 혼재
- 기각: "만드는 주체는 안 합친다"는 사용자 의도와 어긋남. 봇은 엔진, routine은 서사라는 역할 분리(v2 헌장②) 유지가 낫다.

### B. routine 단독 + 봇이 검증 현황 fallback 카드 발송

- 장점: routine 실패해도 검증 현황은 봇이 자동 백업 → 완전 무인
- 단점: 봇 fallback 카드는 회고 없는 **반쪽짜리**(검증 현황만)라, 통합 카드와 내용·형식이 들쭉날쭉
- 기각: 사용자가 "백업 카드가 routine 결과와 달라진다"를 지적. 형식 일관성을 위해 알림+수동 재실행(C)으로 대체.

### C. routine 단독 + 봇 알림 + 수동 재실행 (선택)

- 장점: 항상 동일한 한 장(통합 카드), 침묵 없음(봇 알림이 확실히 감), 봇은 카드 생성 로직 불필요
- 단점: routine 실패 주에 사용자의 수동 개입 1회 필요(자동 아님) — 단 사용자가 수용
- 보강 전제: idempotency를 발송 성공 기준으로(결정 4) 바꿔야 수동 재실행이 항상 동작

### posterior 노출 — 유지 vs 제거

- 유지(기각): `확신 N%` 라벨이 발현일 적중률을 "패턴 확신도"로 오독시키고 표본과 중복. #434 헌장⑤("50%=우연" 안내 텍스트)는 *임의 임계 회피* 취지지 posterior 표시 의무가 아니므로, 제거해도 헌장 위반 아님 — 오히려 오독 제거로 정직성 개선.

## Consequences

### 장점

- 사용자는 매주 비슷한 카드 두 장 대신 **한 장**(회고 + 근거 통계)을 받는다.
- 시드/신호 라벨이 전 카드에서 일관(통합·발굴·시드영향력).
- `확신` 오독 제거 + 표시 지표 슬림화로 가독성·정직성 동시 개선.
- 봇/ routine의 역할 분리(엔진 vs 서사)는 유지 — 통계는 여전히 결정론이 계산.

### 단점 / 제약

- routine(Claude 앱)이 봇보다 실패 가능성이 높아, 실패 주엔 사용자 수동 재실행 1회 필요.
- 통계 표시를 LLM이 옮기는 구조 → "쿼리값 그대로" 프롬프트 가드에 의존(코드 강제는 아님).
- 봇 `buildVerificationBlocks`/`buildSeedInfluenceSection` 등 발송 경로가 죽은 코드가 됨 → 정리 필요.

### 후속 작업

- [ ] routine SKILL: 통합 카드 구조 + 검증 현황 쿼리(effect·status 카운트) + idempotency 발송 성공 기준 + 라벨 표기 규칙
- [ ] 봇: 패턴 검증 카드 발송 제거, 월 늦은 시각 "routine 미발송 알림" 슬롯 추가
- [ ] `insight-labels.ts` 라벨 단축 + 영향받는 봇 카드/테스트 동기화
- [ ] 죽은 발송 코드(`buildVerificationBlocks` 등) 정리 범위 확정
- [ ] 추세(주간 대비) 표시는 데이터 안정화(1\~2달) 후 별도 검토 — 본 ADR 범위 밖
