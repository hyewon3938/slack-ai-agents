# 0012. 운세 분석 개인화 — 라이프 테마 두 트랙 + 의사결정 가이드 + 자연 prose

- Status: Accepted
- Date: 2026-05-08
- Related: #383
- Tags: data, llm, ux

## Context

기존 `fortune_analyses.analysis`는 사주 해석 위주로 작성되어, 다음 한계가 있었다.

- **active life_themes 연결이 약했다** — 분석이 "오늘 일주의 십성"에 머물고, 사용자의 현재 관심사(이직 준비/재정/건강 등)와 잘 엮이지 않았다.
- **의사결정 가이드가 없었다** — "약속 잡아도 되는지", "오늘 외출이 좋은지" 같은 직접적 결정에는 도움이 적었다.
- **fortune_analyses 5개 필드 활용이 불균질했다** — `summary` / `advice`가 표시 경로(insightMorningTask, formatFortune)에서 일부만 노출되거나 누락. `warnings` / `recommendations`는 본문과 중복되는 슬롯이라 흐름이 끊겼다.
- **톤이 "잔소리꾼 친구" 일변도** — 사용자는 명리학을 학습한 상태라, 십성/지장간/합충형 등 전문 용어를 자유롭게 풀어주는 톤이 더 적합한데도 잔소리에 집중했다.

design 1(#382 cross-domain saju_patterns) 머지 직후, 운세 분석 자체의 깊이를 높이기 위한 개편이 필요했다.

## Decision

운세 분석 생성 정책(`weekly-fortune` SKILL.md)과 표시 경로를 다음과 같이 통일한다.

### 1. 분석 프레임워크 6 → 8 관점

기존 6개 관점(십성/합충형/십이운성/월운 맥락/개인 패턴/삶의 테마)에 두 관점을 추가한다.

7. **의사결정 가이드** — LLM이 그 날 흐름에 맞는 결정 항목 3\~5개를 자유 선택. 고정 슬롯 X. 카테고리 후보(약속/외출/이직 준비/재정 결정/대화/혼자 시간/운동/학습)는 가이드일 뿐, 선택은 LLM 재량.
8. **잠재 카테고리 surface** — `day_pillar` 십성 → 활성 영역 매핑으로 추론. active life_themes에 포함되면 강한 직접 연결, 미포함이면 한 문장으로 부드럽게 surface.

### 2. 라이프 테마 연결 두 트랙

- **활성 트랙** — `life_themes.active = true` 항목과 본문에서 명시적 연결 + 의사결정 가이드 직접 제공.
- **잠재 트랙** — 사주 원국 + 운 흐름에서 활성화되는 영역 추론. 사용자가 의식하지 못한 영역도 운에서 자동 짚어주기.

십성 → 잠재 영역 매핑:

| 십성 | 잠재 영역 |
|------|----------|
| 식상 (식신/상관) | 표현/창조/연애(여자) |
| 재성 (정재/편재) | 재물/소비/연애(남자) |
| 관성 (정관/편관) | 직장/명예/연애(여자)/스트레스 |
| 인성 (정인/편인) | 학습/문서/계약/부모 |
| 비겁 (비견/겁재) | 동료/경쟁/자존 |

### 3. 출력 — 자연 prose

- 마크다운 헤더(`#`, `##`) 금지
- 이모지 금지
- 라벨/머리말(예: "오늘의 핵심:") 금지
- 단락 구분은 빈 줄만
- "보고서" 톤이 아닌 "개인화된 메시지" 톤

### 4. fortune_analyses 필드 활용 — summary + analysis + advice 세 필드만

| 필드 | 용도 |
|------|------|
| `summary` | 한 줄 hook (50자 내외, Slack 첫 줄에 *볼드*) |
| `analysis` | 본문 (자연 prose, 단락 빈 줄 구분) |
| `advice` | 한 줄 명리학적 격언/권유 (마지막에 _기울임_) |
| `warnings` | **빈 배열 `'[]'::jsonb`** — 본문에 녹임 |
| `recommendations` | **빈 배열 `'[]'::jsonb`** — 본문에 녹임 |

표시 경로는 공유 헬퍼 `src/shared/fortune-format.ts`의 `formatFortuneText`로 통일.

### 5. 톤 — "명리학자가 애정을 담아 풀어주는"

- 사용자는 명리학 학습 상태 → 십성/지장간/합충형 등 전문 용어 자유롭게 사용 (단, 풀이 곁들여 의미 있게)
- **사실 숨기지 않음** — 흉운도 부드럽게 풀이하되 솔직하게 (애정 때문에 사실 왜곡 X)
- 권유형 위주: "\~하면 좋겠어", "\~하는 게 좋겠어"
- 잔소리는 한 문장 안에 끝, 명리 풀이가 본문 주축

### 6. period별 길이 가이드

| period | analysis 길이 | advice |
|------|----------|------|
| daily | 350\~500자 | 1\~2문장 |
| monthly | 600\~800자 | 1\~2문장 |
| yearly | 800\~1200자 | 1\~2문장 |
| major | 800\~1200자 | 1\~2문장 |

## Alternatives considered

### A. 의사결정 가이드를 고정 카테고리 슬롯으로 (이직/약속/외출/재정 4개)

- 장점: 출력 일관성. LLM이 빠뜨리지 않음.
- 단점: 모든 항목이 동등 비중으로 강제됨 → **그 날의 실제 우선순위 시그널이 소실**. 평운/길운/흉운 모두 같은 슬롯을 채우게 되어 "그 날 진짜 중요한 게 뭔지" 안 보임.
- 기각 이유: 운세의 핵심은 우선순위 시그널인데 슬롯은 그걸 죽인다.

### B. 출력을 보고서 구조로 (이모지 + 헤더 + 라벨 분리)

- 장점: 정보 탐색 용이. "주의사항만 빨리 보기" 같은 사용 패턴 지원.
- 단점: 개인 운세에서 "리포트" 톤은 거리감을 만듦. 사용자 선호상 부합 X.
- 기각 이유: "명리학자가 애정을 담아" 톤과 정면 충돌.

### C. warnings/recommendations 별도 필드 활용

- 장점: 스키마에 이미 있는 필드 활용. UI에서 분리 표시 가능.
- 단점: 본문 흐름이 끊기고, analysis와 중복되는 정보를 별도 슬롯에 채우게 됨. LLM이 같은 내용을 두 번 작성하게 되어 토큰 낭비 + 일관성 저하.
- 기각 이유: 자연 prose 결정과 충돌. 빈 배열로 두고 본문에 녹이는 게 깔끔.

### D. 잠재 카테고리 없이 활성 life_themes만

- 장점: 구현 단순. 사용자 명시 항목만 다루므로 관련성 높음.
- 단점: 사용자가 의식하지 못한 영역(운 흐름)을 놓침. "생각도 못했던 걸 잡아주는" 가치 소실.
- 기각 이유: 운세의 핵심 가치 중 하나가 "미인식 영역 surface"인데 그걸 포기하면 일반 일정 알림과 차이가 약해진다.

### E. 선택한 안 — 8 관점 + 두 트랙 + 자연 prose + 세 필드

- 장점:
  - 우선순위 시그널 보존 (LLM 자유 선택)
  - 활성/잠재 두 축으로 의식·무의식 영역 모두 커버
  - 표시 경로 단순화 (세 필드만)
  - 톤이 "보고서"가 아닌 "개인화된 메시지"로 정착
- 단점:
  - SKILL.md 분석 프레임워크 복잡도 증가 → LLM 토큰 사용량 증가 가능
  - 잠재 카테고리 매핑이 단순 휴리스틱 (실제 명리는 더 복잡) — 정확도는 LLM 판단에 의존

## Consequences

### 장점

- 출력의 개인화 깊이 향상 — "오늘 일주 + 십성" 수준에서 "활성 테마 + 잠재 영역 + 의사결정 가이드"로 확장
- 의사결정 직접 도움 (이직/약속/외출 등) — 막연한 권유가 아닌 그 날 흐름에 맞는 구체 결정 가이드
- 운에서 활성화되는 영역 자동 surface — 사용자 미인식 영역도 짚어줌
- 톤이 "보고서"가 아닌 "개인화된 메시지"로 정착
- 표시 경로 통일 (공유 헬퍼 `formatFortuneText`) — insightMorningTask, formatFortune 두 곳이 동일 포맷 사용 → 향후 변경 시 한 곳만 수정

### 단점 / 제약

- weekly-fortune 토큰 사용량 증가 가능 (8 관점 + 두 트랙 + period별 길이 차등화)
- 잠재 카테고리 매핑이 휴리스틱 — 케이스에 따라 LLM이 잘못 적용할 가능성. 모니터링 필요.
- SKILL.md가 git 비추적 외부 파일(`~/.claude/scheduled-tasks/weekly-fortune/SKILL.md`) — 수정 후 백업/동기화 부담
