# 사주 부록 — 시드 출처로서의 사주

> 이 문서는 [프로액티브 인사이트 v2 메인 explainer](insight-v2.md)의 부록이다. 메인은 "개인 라이프 패턴 발견 시스템"을 4가지 핵심 개념(시드·신호·가설·검증)으로 설명한다. 이 부록은 그 안에서 **시드 출처 중 하나인 사주**가 구체적으로 어떻게 정의되는지 깊게 풀어 쓴다.

---

## 0. 이 부록은 누구를 위한 것인가

- 메인 explainer를 다 읽은 뒤, "사주 시드가 구체적으로 무엇인지" 더 보고 싶은 사람
- 사주를 모르는 사람도 따라올 수 있게 미니 101 포함 — 다만 이건 **사주 입문서가 아니다**. 이 시스템이 사주를 어떻게 다루는지 따라가기 위한 최소 사전이다.
- 사주를 안 믿거나 관심 없는 사람은 메인 explainer만 읽으면 된다. 이 부록은 건너뛰어도 시스템 이해에 부족함 없음.

> **다시 한번**: 이 시스템은 사주를 **검증하지 않는다.** 사주에서 가져온 글자 집합을 **시드 풀의 한 출처**로 쓸 뿐이고, 그 시드가 실제 내 데이터와 연관이 있는지는 다른 모든 시드와 똑같이 off-day 통계로 채점된다. 아래 명리학 규칙들은 "무엇을 시드로 삼을지" 정하는 단계일 뿐, 효과를 단언하지 않는다.

다섯 묶음(비겁=비견+겁재 / 식상=식신+상관 / 재성=편재+정재 / 관성=편관+정관 / 인성=편인+정인)으로 합치면 5그룹이 된다. 뒤의 강도·효과적 십성 계산이 이 5그룹을 쓴다.

| 목욕(沐浴) | 정리·세정, 변화 직전 |

### 1-6. 본인 사주 = 4기둥 8글자 + 운(運)

사주의 "사주(四柱)"는 네 기둥. 태어난 **년·월·일·시** 각각에 천간 1자 + 지지 1자가 붙어 총 8글자.

```
            년주    월주    일주    시주
천간       □     □     ★     □       ← ★이 일간 (본인 기준점)
지지       □     □     □     □
```

이 8글자가 **원국**(natal chart). 변하지 않는다.

이 위에 시간 단위로 운이 흐른다:

| 운 레벨 | 단위 | 변동 주기 |
|---|---|---|
| 대운 | 천간 1자 + 지지 1자 | 10년 |
| 세운 | 천간 1자 + 지지 1자 | 1년 |
| 월운 | 천간 1자 + 지지 1자 | 약 1개월 (24절기 기준) |
| 일운 | 천간 1자 + 지지 1자 | 1일 |

**대운**은 출생 시각·성별에 따라 시작 나이와 흐름 방향이 결정된다.

## 2. 운 레벨 차원

이 시스템은 **5개 운 레벨**을 동시에 다룬다. 시드는 "어느 운 레벨에서 발현되는가"를 명시한다.

```
┌─────────────────────────────────────────────────┐
│  원국 (natal) — 변하지 않음                      │
│   천간 4 + 지지 4 = 8자                          │
└─────────────────────────────────────────────────┘
            │
┌───────────┴─────────────────────────────────────┐
│  대운 (10년) — 천간 1 + 지지 1                   │
└─────────────────────────────────────────────────┘
            │
┌───────────┴─────────────────────────────────────┐
│  세운 (1년) — 천간 1 + 지지 1                    │
└─────────────────────────────────────────────────┘
            │
┌───────────┴─────────────────────────────────────┐
│  월운 (약 1개월) — 천간 1 + 지지 1               │
└─────────────────────────────────────────────────┘
            │
┌───────────┴─────────────────────────────────────┐
│  일운 (1일) — 천간 1 + 지지 1                    │
│   ★ 매일 07:00 매칭 cron의 주된 평가 대상         │
└─────────────────────────────────────────────────┘
```

`pattern_catalog.pillar_level` 컬럼이 이 5개를 enum으로 갖는다 (ADR-0028). (원래 '누적(cumulative)' 차원이 하나 더 있었으나 #508에서 은퇴 — §4 참조.)

- 매일 트리거 평가는 주로 **일운** 차원에서 일어난다.
- 운 레벨이 강도에 주는 영향(modulation)은 통계 상호작용으로 검증하지 않고, **결정론 규칙으로 "실효 강도" feature를 계산**해 시드로 환원한다(§5, #477 P4). 일운 한 차원에 갇히지 않게 하는 장치다.

## 3. 사주 일운 6종 — trigger_target_type

`pattern_catalog.trigger_target_type`은 현재 9종 enum이다 (`cumulative_pillar_count`가 #508에서 은퇴해 10종 → 9종).

```
stem · branch · ganji · element_density · sibiunsung · relation   ← 사주 일운 6종 (이 부록 §3)
strength_band · hwa_sipsung                                       ← 결정론 사주 feature 2종 (§5, #477 P4)
life_signal                                                       ← 라이프 1종 (메인 §5)
```

사주 계열은 8종(일운 6 + feature 2), 라이프가 1종이다. 이 부록은 일운 6종을 §3, feature 2종을 §5에서 다룬다(§4는 은퇴한 누적 차원의 기록). `life_signal`은 메인 explainer §5에서 설명.

### 3-1. stem (천간)

- **의미**: 일운의 천간이 본인 사주의 특정 글자
- **trigger 예시**: 일운 천간 = 갑(甲)인 날
- **시드 수**: 12
- **trigger 평가**: 오늘 일운 천간 SQL 추출 → `trigger_target` 문자열과 비교

### 3-2. branch (지지)

- **의미**: 일운의 지지가 본인 사주의 특정 글자
- **trigger 예시**: 일운 지지 = 오(午)인 날
- **시드 수**: 15
- **통합 시드**: 본인 일지와 같은 지지가 일운에 들어오는 날을 통째로 묶은 시드도 포함 (`trigger_aux = {"mode": "match_day_branch"}`)

### 3-3. ganji (60갑자)

- **의미**: 일운 천간 + 지지 조합(60갑자) 1개와 일치
- **trigger 예시**: 일운 = 갑오(甲午)인 날
- **시드 수**: 60
- **참고**: 모든 60갑자 시드가 동등하게 평가됨. "본인 일주와 같은 갑자가 들어오는 날" 같은 직관은 시드 description에 박혀 있고 LLM 신호 제안 단계에서 활용될 수 있다.

### 3-4. element_density (오행 밀도)

본인 사주 8자 + 일운 2자 = 총 **10자** 중 특정 오행이 N개 이상(또는 이하)인 날.

- **의미**: 오행 비율 임계치 트리거
- **trigger 예시**: 10자 중 토 오행이 5개 이상인 날
- **시드 수**: 10
- **trigger_aux 표준**:
  ```json
  {"element": "화", "mode": "over"}    // 특정 오행 N개 이상
  {"element": "화", "mode": "lack"}    // 특정 오행 N개 이하 (예: 0~1)
  ```

본인 원국 8자는 고정이므로 element_density는 일운 2자에 따라 결정된다. 이건 "원국이 무슨 글자로 구성됐나"를 보는 단순 카운트로, 뒤의 실효 강도(§5)와 구분된다.

### 3-5. sibiunsung (12운성)

본인 **일간**을 기준으로 일운 **지지**의 12운성 분류.

- **의미**: 일운 지지가 본인 일간에게 어떤 생애 곡선 단계인지
- **trigger 예시**: 본인 일간이 갑(甲) → 일운 지지가 오(午) → 12운성 = 사지(死). "사지가 들어오는 날"
- **시드 수**: 12
- **trigger_aux 표준**: `{"name": "장생"}` 등 12운성 이름 1개

12운성 lookup table이 천간 10 × 지지 12 = 120개 매핑을 보관. 본인 일간이 결정되면 일운 지지에 대한 12운성이 한 번 lookup으로 결정.

### 3-6. relation (지지·천간 관계)

본인 사주 글자와 일운 글자 사이의 **관계**.

- **의미**: 본인 지지/천간과 일운이 합·충·형·파·해·원진·귀문·암합 등 관계를 맺는 날
- **trigger 예시**: 본인 일지 = 진(辰), 일운 지지 = 술(戌) → "진술충" 발현
- **시드 수**: 82 (#477 P4b에서 귀문·대표 암합 추가로 확장)
- **trigger_aux 표준**:
  ```json
  {"position": "day", "relation": "충", "pair": ["진", "술"]}
  ```

| 관계 | 한 줄 의미 (일반 통념) |
|---|---|
| 합(合) | 결합·끌어당김. 육합·삼합·방합 등 세부 분류 |
| 충(沖) | 충돌·흔들림 |
| 형(刑) | 마찰·고생 |
| 파(破) | 깨짐 |
| 해(害) | 방해 |
| 원진 | 미묘한 갈등 |
| 귀문 | 예민·강박 (#477 추가) |
| 암합 | 드러나지 않는 끌림 (#477 추가) |

관계 풀은 본인 지지·천간 × 일운에 대해 사전 계산되어 있고, 원국에 없는 쌍은 휴면(발현 0)이다.

> 모든 관계의 "통념적 의미"는 그대로 검증 대상이 아니다. 이 시스템은 각 관계가 들어오는 날 사용자 신호 발현을 측정해 통계로 가설을 채점할 뿐.

## 4. (은퇴) cumulative_pillar_count 누적

> **#508(ADR-0046)에서 은퇴, #514에서 코드 제거.** 원래 5개 운 레벨(원국·대운·세운·월운·일운) 중 특정 오행/십성이 몇 레벨에 발현됐는지 세는 누적 카운트 시드(화 오행·편재 N=1..5, 10개)가 있었다. 하지만 고정 임계라, 본인 사주처럼 특정 기운이 운에 늘 깔린 경우 매일 발현 → off-day(비발현일)가 사라져 통계 검정이 불가능했다(영영 확정 불가).
>
> 같은 "오늘 이 기운이 평소보다 강한가"는 §5의 **강도 밴드**(상대 분위수 + 주간 재계산)가 포화 없이 더 정밀하게 측정하므로, 누적 시드를 강도 밴드로 위임·archive하고 트리거 평가 코드까지 데드코드로 제거(#514)했다. 분포 분석 cron(월 09:15)도 함께 은퇴.

## 5. 결정론 사주 feature — 강도와 합화 (#477 P4)

§3\~§4의 시드들은 글자가 "있다/없다"를 보는 비교적 단순한 트리거다. #477 P4는 여기에 명리학의 **정도(degree)** 개념을 결정론 규칙으로 계산해 시드로 추가했다.

핵심 설계는 메인 §5에서 짚은 것과 같다 — **명리학(결정론 feature 계산) ↔ 통계(나에게 유효한가 검정)를 분리**한다. 아래 규칙들은 feature를 *계산*만 하고 효과를 *단언*하지 않는다. 틀린 규칙으로 만든 feature는 off-day 대조에서 연관이 안 나와 자연히 걸러진다. 규칙은 하드코딩이 아니라 파라미터로 두어, 명리학 학파에 따라 끌 수 있다 (ADR-0033·0036·0038).

### 5-1. 실효 강도 → strength_band (강도 밴드)

어떤 오행/일간이 그날 얼마나 "센지"를 하나의 수치(실효 강도)로 계산한다.

```
실효 강도 = 생조(인성 + 비겁) − 극설(식상 + 재성 + 관성)
            + 월령(득령 보정) + 통근(뿌리 보너스)
```

- 운 풀셋(원국 4기둥 + 대운·세운·월운·일운)의 글자를 위치 가중해서 합산한다. 일운 2글자가 매일 바뀌므로 강도도 매일 변동한다.
- 일간 강도(신강/신약)와 오행 5개 강도를 모두 산출한다.
- 가중치·월령 배수·통근 조건은 전부 config 파라미터다 (명리학 프레임 정본, 통계 노브와 분리).

이 강도를 **상대 분위수**(tertile)로 3등분해 시드로 만든다 — 약(low) / 적정(mid) / 강(high).

| trigger_target_type | aux 예 | 의미 |
|---|---|---|
| `strength_band` | `{"target":"day_master","band":"high"}` | 일간 강도가 본인 분포 상위 1/3인 날 |
| `strength_band` | `{"target":"화","band":"low"}` | 화 오행 강도가 본인 분포 하위 1/3인 날 |

- **시드 수**: 18 (일간 + 5오행 × 3밴드)
- **왜 절대 기준이 아니라 분위수인가**: 남과 비교하는 시스템이면 절대 기준이 맞지만, 이건 **자기 안에서 패턴을 찾는** n=1 시스템이라 본인 분포의 분위수가 의미 단위다 (ADR-0036). 강도는 대부분 고정된 원국에서 오고 매일 바뀌는 건 일운 2글자뿐이라, 절대 컷을 쓰면 한 밴드로 쏠려 off-day 대조가 무너진다. 분위수는 일운 변동을 항상 3등분해 포착한다. (절대 신강/신약 상태도 버리지 않고 병행 계산해 맥락으로 보존.)
- 비단조(inverted-U: 적정→+ / 과다→−) 패턴도 밴드별 독립 시드라 자연히 잡힌다 — 약·적정·강 밴드가 각각 따로 검증되므로.

### 5-2. 합화 변환 → hwa_sipsung (효과적 십성)

합(천간합·육합·삼합)이 **화(化)신 통근 조건**을 만족하면, 구성 글자의 오행이 변한 오행(化 오행)으로 바뀐다. 예를 들어 갑(목)과 기(토)가 합해 토로 화하면, 그날 그 글자들은 토로 계산된다.

- 합화 변환은 강도 계산(§5-1)의 **입력단에서 한 번 적용**된다 — 별도 시드가 아니라 강도·밴드·효과적 십성이 전부 변환된 글자 기준으로 일관되게 계산되도록.
- 해소 깊이는 보수적인 1차 버전(합 성립 + 충개합)이고, 더 깊은 명리 규칙(탐합망충·쟁합·형파 등)은 파라미터 노브로 두되 기본은 꺼둔다 — n=1 \~90일 데이터로는 깊은 정밀도가 검증 불가능(구분 안 됨)하고, 학파별 선택지가 많아 자기기만 여지를 키우기 때문이다. **깊은 명리 해석은 검증이 아니라 별도 LLM 해석 트랙의 몫**이다 (ADR-0038).

합화 변환의 결과로 화한 오행의 **일간 대비 십성**(5그룹: 비겁/식상/재성/관성/인성)이 바뀌는데, 이 "효과적 십성"이 들어오는 날을 시드로 둔다.

| trigger_target_type | aux 예 | 의미 |
|---|---|---|
| `hwa_sipsung` | `{"sipsin":"재성","via":"hwa"}` | 합화 후 化 오행이 일간 대비 재성이 되는 날 |

- **시드 수**: 5
- 합화 성립일에만 발현하므로 드물게(sparse) 켜진다 — 대부분의 날 휴면.

### 5-3. FDR 가족 격리

강도·관계 시드는 자주 발현해서, 그대로 두면 빠른 `life_signal` 트랙(주말·월말)의 확정을 늦춘다. 그래서 검증의 다중비교 보정(BH-FDR)을 **세 가족으로 분리**한다 (ADR-0037·0038): `saju_strength`(강도 밴드) / `saju_relation`(관계·효과적 십성) / `baseline`(그 외). 가족 안에서만 서로 경쟁하게 해서 빠른 트랙을 보호한다.

## 7. 기간 해석 — 검증가능성 사다리 + 예측 장부 (#523)

여기까지(§1\~6)는 **일운**(하루 단위) 시드를 통계로 검증하는 얘기였다. 일운은 표본이 수백 일이라 off-day 대조 + e-value로 진짜 실증이 된다. 그런데 사주엔 일운 위에 더 큰 주기가 있다 — 월운(\~1개월)·세운(1년)·대운(10년). 이걸 일운 검증 엔진이 학습한 개인화 반응과 잇는 게 #523이다 (#408 5-B 구체화).

핵심 긴장: **단위가 커질수록 표본이 기하급수로 줄어 통계 확정이 불가능해진다.** 세운은 평생 몇 번, 대운은 평생 대여섯 번뿐이다. 그래서 "검증된 척"을 구조적으로 막는 게 이 확장의 1차 목표다.

### 7-1. 검증가능성 사다리

각 층의 **인식 지위를 다르게** 두고, 출력 카드마다 그 지위를 라벨로 동반한다 (ADR-0050).

| 층 | 단위 | 지위 | 근거 |
|---|---|---|---|
| 일운 | 하루 | **실증** | off-day 2×2 + e-value (§1\~6) |
| 월운 | 절기달 | **축적-실증** | 예측 장부(생성→채점) + 누적 기술통계. 월 단위 e-게이트는 금지(월 표본이 수년간 한 자릿수) |
| 세운 | 입춘년 | **장부 한정 약실증** | 입춘 예측 → 다음 입춘 채점. 수명 내 n=1\~2 — 통계 확정 영구 불가 |
| 대운 | 10년 | **비실증 추론** | 검증 불가 명시. 교과서 일반론 + 가중치 참고만 |

카드에는 이 지위가 문장으로 박힌다 — 예를 들어 세운 카드 하단에 "_세운은 평생 표본이 한두 번뿐 — 통계로 확정은 영구히 못 해, 경향 참고용_". 검증 안 되는 걸 숨기지 않는다.

### 7-2. 전이 가설 (미검증 가정)

상위 주기 해석은 "**일 단위에서 측정된 반응이 더 큰 주기에도 같은 방향으로 이어진다**"는 가정 위에 선다. 이걸 **전이 가설**이라 부른다.

중요한 건, 전이 가설은 §1\~6의 시드처럼 `pattern_catalog`에 등록돼 e-value로 채점되는 가설 **엔티티가 아니다.** ADR 결정 + 모든 상위 카드에 따라붙는 hedge 라벨로만 존재하는 **메타 가정**이다. 시스템은 이걸 사실로 단정하지 않고, §7-4 장부가 시간을 들여 *간접적으로* 시험한다.

### 7-3. 측정 vs 교과서 분리 발화

상위 주기 카드는 두 재료를 **절대 섞지 않고** 나눠 말한다:
- **측정된 반응** — 일운 검증 엔진이 학습한 개인화 프로필(`saju_response_profile`)에서 이 기간 글자에 해당하는 셀이 있으면, tier(검증됨/검증중) 라벨과 함께.
- **교과서 일반론** — 명리 일반론. "교과서적으론 \~인데 네 데이터엔 아직 안 잡혀" 톤으로, 측정된 것처럼 단정 금지.

데이터가 얇아 측정 셀이 0이어도 카드는 빈손이 아니다 — 교과서 + 누적 기술통계 + 사다리 라벨로 채운다. **침묵 금지, 무증거를 증거처럼 말하기도 금지.**

### 7-4. 예측 장부 — 확증편향 차단 (월·세만)

검증 불가 층이라도 **사전등록 → 사후채점** 장부는 가치가 있다 (`period_forecasts`, ADR-0050):

1. 절기/입춘 전환일에 시스템이 이번 기간 top-3 예측을 **미리** 적고(어느 방향으로 갈지) **봉인**한다. 예측할 게 없으면 "예측 안 함(no-call)"도 명시.
2. baseline(비교 기준)은 **생성 시점에 동결** — 사후에 데이터에 맞춰 바꿀 수 없다. 이게 확증편향("맞은 것만 기억")을 구조적으로 막는다.
3. 다음 전환일에 자동 채점 — **방향 적중 + 실측 변화량**(delta)만 기록한다. 표본이 없는 층에서 Brier 같은 확률 점수는 과대주장이라 금지.

장부는 **월운·세운만** 만든다. 대운(10년)은 채점 주기가 수명을 넘어 장부로도 무의미해 비편입.

자기검증 메커니즘: 생성도 채점도 **절기/입춘 시간 게이트 하나로 무인** 작동한다. 멱등(재실행 안전) + baseline 동결 + 놓친 전환 자가 회수라, 손대지 않아도 시간이 흐르며 성적표가 쌓인다 — "메커니즘을 완성해두면 시간이 스스로 검증한다."

### 7-5. 카드는 어떻게 오나

- **자동**: `periodFortune` cron이 매일 깨어 절기/입춘/대운 전환을 감지, 전환일에만 #insight로 카드 발송(평일 no-op). 서사는 Opus가 쓴다.
- **조회**: `월운`/`세운`/`대운`을 입력하면 저장된 최신 해석(+ 월·세 장부)을 LLM 없이 즉시 렌더.
